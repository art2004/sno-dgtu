# СНО ДГТУ — учёт мероприятий

Веб-приложение для студенческого научного общества ДГТУ (Донской государственный технический университет): учёт участий членов совета в грантах, конференциях, конкурсах, стипендиях и статьях, журнал заседаний и мероприятий СНО и генерация отчёта «Отчет о проведенных заседаниях СНО» в Word.

## Стек

- Python 3.10+
- [Streamlit](https://streamlit.io/), графики — Plotly
- База данных: **Postgres** (например, бесплатный [Neon](https://neon.tech)) или локальная **SQLite** (`data/sno.db`)
- SQLAlchemy 2 + psycopg 3, bcrypt (хэши паролей)
- python-docx (отчёт .docx), openpyxl (выгрузка .xlsx)

## Как выбирается база данных

1. `DATABASE_URL` из Streamlit Secrets (`.streamlit/secrets.toml` или Secrets в Streamlit Cloud);
2. иначе переменная окружения `DATABASE_URL`;
3. иначе — локальная SQLite `data/sno.db` (создаётся автоматически).

Адреса `postgres://…` и `postgresql://…` (как выдаёт Neon) подходят без изменений.

## Быстрый старт (локально, SQLite)

```bash
python -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt
streamlit run app.py
```

Откройте адрес, который покажет Streamlit (обычно http://localhost:8501).

**Администратор при первом запуске.** Если в базе нет ни одного админа, он создаётся автоматически:

- логин — `ADMIN_LOGIN` (по умолчанию `admin`);
- пароль — `ADMIN_PASSWORD`. Только для локальной SQLite без `ADMIN_PASSWORD` используется временный пароль `admin123` — смените его сразу после входа.

На Postgres без `ADMIN_PASSWORD` админ **не создаётся**, а на странице входа показывается подсказка, что нужно задать пароль в Secrets.

Чтобы локально подключиться к Postgres, скопируйте `.streamlit/secrets.toml.example` в `.streamlit/secrets.toml` и заполните значения (или задайте переменные окружения `DATABASE_URL`, `ADMIN_LOGIN`, `ADMIN_PASSWORD`).

## Смена пароля

Любой вошедший пользователь может сменить свой пароль: боковая панель → **🔑 Сменить пароль** (текущий пароль, новый, повтор; не менее 8 символов). Админ также может задать новый пароль любому участнику во вкладке «Участники».

## Вход сохраняется после обновления страницы

После входа браузер получает cookie `sno_auth` на 30 дней (Path=/, SameSite=Lax, Secure при https), поэтому обновление страницы или перезапуск браузера не разлогинивает. В cookie только id пользователя, срок действия и подпись HMAC — ни пароля, ни его хеша там нет. Cookie перестаёт действовать, если пароль изменён (самим пользователем или админом), учётная запись отключена или удалена. «Выйти» удаляет cookie; после «Сменить пароль» текущий браузер получает новую cookie, а старые на других устройствах перестают работать (при следующем обновлении страницы).

Ключ подписи: секрет `COOKIE_SECRET`, если он задан; иначе случайный ключ создаётся один раз и хранится в таблице `settings` базы данных — добавлять новые секреты не нужно. Смена ключа (или `COOKIE_SECRET`) разлогинивает всех.

1. Зарегистрируйтесь на [neon.tech](https://neon.tech) и создайте проект (**New Project**), регион — ближайший (например, Frankfurt / `eu-central-1`).
2. На панели проекта нажмите **Connect**, выберите роль и базу (по умолчанию `neondb`) и скопируйте **connection string** вида
   `postgresql://USER:PASSWORD@ep-xxxx.eu-central-1.aws.neon.tech/neondb?sslmode=require`.
3. Таблицы создавать вручную не нужно — приложение создаст их при первом запуске.

### 2. Код на GitHub

1. Создайте репозиторий на GitHub (можно приватный).
2. Загрузите файлы проекта: `app.py`, `db.py`, `auth.py`, `report.py`, `ru_text.py`, `templates/sno_meetings_template.docx`, `requirements.txt`, `README.md`, `smoke_test.py`, `.gitignore`, `.streamlit/secrets.toml.example`.
   **Не загружайте** `.venv/`, `data/*.db` и `.streamlit/secrets.toml` — они уже в `.gitignore`.

```bash
git init
git add .
git commit -m "СНО ДГТУ: учёт мероприятий"
git branch -M main
git remote add origin https://github.com/<ваш-логин>/<репозиторий>.git
git push -u origin main
```

### 3. Приложение в Streamlit Community Cloud

1. Зайдите на [share.streamlit.io](https://share.streamlit.io) через GitHub (для приватного репозитория разрешите доступ к нему).
2. **Create app** / **New app** → «Deploy a public app from GitHub»: выберите репозиторий, ветку `main`, **Main file path** — `app.py`.
3. Откройте **Advanced settings**, выберите версию Python (3.11 или 3.12) и в поле **Secrets** вставьте в формате TOML:

```toml
DATABASE_URL = "postgresql://USER:PASSWORD@ep-xxxx.eu-central-1.aws.neon.tech/neondb?sslmode=require"
ADMIN_LOGIN = "admin"
ADMIN_PASSWORD = "придумайте-надёжный-пароль"
```

4. Нажмите **Deploy** и дождитесь сборки.
5. Секреты можно изменить позже: меню приложения → **Settings → Secrets** (после сохранения приложение перезапустится).

### 4. Первый вход

1. Войдите с `ADMIN_LOGIN` / `ADMIN_PASSWORD` из Secrets.
2. Сразу смените пароль: боковая панель → **🔑 Сменить пароль**.
3. Добавьте членов совета во вкладке «Участники».

`ADMIN_PASSWORD` используется только для создания самого первого админа; последующие изменения этого секрета не меняют пароль уже существующего админа.

`ADMIN_LOGIN`/`ADMIN_PASSWORD` срабатывают только когда в базе **нет ни одного** админа. Роли, изменённые вручную во вкладке «Участники», при перезапуске не откатываются: если, например, пользователь `admin` разжалован в члены совета, а админом стал другой участник, секреты ничего не меняют.

> Бесплатный Neon «засыпает» при простое — первый запрос после паузы может занять несколько секунд. Streamlit Cloud тоже усыпляет приложения без посещений; данные при этом сохраняются в Neon.

## Роли

- **Админ (лидер СНО)** — вкладки: **Участники** | **Статистика** | **Заседания и мероприятия** | **Отчёт** | **Все достижения** | **Настройки**.
- **Член совета** — добавление, редактирование номера достижения и удаление только своих участий; вкладка «Статистика СНО» (только мероприятия, без чужих имён и номеров).

### Смена роли

Вкладка «Участники» → карточка участника → поле **«Роль»** (Член совета / Админ) → «Сохранить». Назначение админом требует подтверждения. Ограничения проверяются в базе данных, а не только в интерфейсе: свою роль изменить нельзя, а последнего активного админа нельзя разжаловать, отключить или удалить. Новая роль (а также новое ФИО/логин, отключение или удаление) применяется у пользователя при следующем действии или обновлении страницы: данные сессии каждый раз перечитываются из базы.

### Импорт участников из Excel

Вкладка «Участники» → **📥 Импорт из Excel**: загрузите .xlsx, в первой строке — заголовки **ФИО**, **Логин**, **Пароль** (регистр и пробелы не важны, порядок любой). Появится предпросмотр со статусом каждой строки (будет создан / логин уже есть — пропуск / ошибка: пустое поле, дубль в файле, недопустимый логин), затем кнопка «Создать N участников». Участники создаются с ролью «член совета», пароли хешируются bcrypt; существующие пользователи никогда не перезаписываются.

## Кабинет члена совета — «Мои достижения»

- Вверху — сводка за текущий год: «В 2026 году у тебя 5 записей: доклад — 2, публикация — 1, …» или дружелюбная подсказка.
- **➕ Добавить достижение**: вид (Доклад, Публикация, Конкурс / кейс-чемпионат, Образовательное мероприятие, Выставка, Охранный документ, Грант, Стипендия, Научный обмен, Фонд содействия инновациям, Научная премия, Научное волонтёрство, …) → подпункт/уровень показателя → поля, нужные именно для этого пункта годового отчёта (например, для доклада — мероприятие, дата, тема, очно/заочно; для гранта — подпункт: заявка / РНФ / Минобрнауки / …).
- **Публикация**: доля участия главного автора обязательна; соавторы — строки «участник СНО из списка или ФИО текстом + доля» (доля обязательна). Проверки: 0 < доля ≤ 100, сумма ≤ 100 (при превышении — живое предупреждение, сохранение заблокировано). В отчёте: «доля участия: 49%, 48%, 1%» в порядке авторов. Статья принадлежит главному автору, у соавторов своей записи и счёта нет. Дубль (DOI или название+год) → предупреждение с именем владельца.
- **Номер достижения (с сайта вуза)** — необязательный, нормализуется (№, латиница → кириллица, тире).
- Список записей по видам, с ✏️/🗑 и значком ⚠ «заполните …» (нет уровня/подпункта, доли, учебного года стипендии и т. п.).
- Вкладка **«Статистика СНО»** — общие цифры по показателям без имён и номеров других участников.

## Все достижения (админ)

- Фильтры: участник, вид, показатель, подпункт, год, «Без номера достижения», «Требуют заполнения». Таблица: ФИО, вид, подпункт, название, дата, «Номер в портфолио», «Есть номер», «В отчёте», что заполнить.
- **➕ Добавить за участника (или от СНО)** — та же форма, плюс виды «только для СНО» (организация мероприятий, соглашения, финансируемые работы, конкурс оценки СНО).
- Редактирование и удаление любой записи (с подтверждением).

## Заседания и мероприятия (админ)

Журнал всех мероприятий СНО для отчёта: **заседания**, а также **конференции, форумы, круглые столы** и др., где выступали члены СНО (поле «Вид»: Заседание / Конференция / Форум / Круглый стол / Другое).

- Форма добавления: дата, время (по умолчанию 13:30), вид, локация (список последних использованных локаций + «другая локация»), тема, формат (несколько из списка: Собрание, Форсайт-сессия, Круглый стол, Проектная сессия, Научный семинар, Конференция, Выступления с докладами, Онлайн-заседание — плюс свой вариант текстом; хранится через запятую).
- **«Добавить из мероприятий участников»** — список мероприятий членов совета за выбранный год, ещё не внесённых в журнал. Выбор заполняет форму: дата, вид (конференция → «Конференция», остальное → «Другое»), тема «Выступление членов СНО в рамках «…»», формат «Выступления с докладами» для конференций; остаётся указать локацию и время. Связанное мероприятие больше не предлагается.
- Фильтр по году, единая нумерация 1..N по дате, редактирование и удаление (с подтверждением).

## Отчёт (админ)

Вкладка **«Отчёт»**: выберите год → **«Скачать отчёт (.docx)»**. Документ повторяет официальный шаблон «Приложение Е — Отчет о проведенных заседаниях СНО «…» в ГГГГ году» (альбомный A4, таблица из 5 колонок, подписи). В таблицу попадают все записи из «Заседания и мероприятия» за год, одной нумерацией по дате.

Шаблон лежит в `templates/sno_meetings_template.docx`: это очищенная копия исходного документа (шапка таблицы + одна строка-образец с плейсхолдерами `{N}`, `{DATE}`, `{TIME}`, `{LOCATION}`, `{TOPIC}`, `{FORMAT}`; в заголовке `{APPENDIX}`, `{SNO_NAME}`, `{YEAR}`; подпись `{POSITION} _______________/{NAME}`). Строка-образец клонируется для каждой записи, поэтому шрифты, границы, ширины колонок и выравнивание совпадают с оригиналом. Шаблон можно поправить в Word (не удаляя плейсхолдеры).

Если за год записей нет — в документе будет только шапка таблицы, а в интерфейсе появится предупреждение.

Этот отчёт (Приложение Е) работает как раньше и не зависит от годового отчёта ниже.

## Годовой отчёт о работе СНО (админ)

На той же вкладке **«Отчёт»**, ниже отчёта о заседаниях — раздел **«Годовой отчёт о работе СНО»**: год → показатели (единиц в отчёте, требуют заполнения, заочных докладов), список предупреждений, предпросмотр количества по 18 показателям, поле «Заключение» (сохраняется для года) и кнопки **«Годовой отчёт (.docx)»** и **«Достижения за год (.xlsx)»** (листы «Достижения», «Показатели», «Заседания»).

Документ повторяет форму «Отчет о работе СНО «…» за ГГГГ год» (альбомный A4, таблицы «Показатель / Количество / Отметка о выполнении…», 18 показателей с подпунктами, нумерация внутри подпункта, заключение, подписанты из «Настроек»). Шаблон форматирования: `templates/sno_annual_template.docx` (без данных примера).

**Правила подсчёта:**
- 1 запись = 1 единица в своём подпункте; итог показателя = сумма подпунктов (0, если пусто).
- В отчёт не попадают записи без уровня/подпункта (они в предупреждениях) и заочные доклады.
- Публикации «Без индексации» — корректные записи (видны в кабинете, статистике и Excel), но в годовой отчёт не печатаются и предупреждений не дают. Старые статьи с индексацией «Без индексации» переносятся именно так.
- Результат конкурса (необязательное поле, например «диплом II степени», «1 место») печатается в конце строки отчёта; «участие» не печатается.
- У стипендий, перенесённых из старой версии (есть только дата), остаётся предупреждение «укажите учебный год».
- Доклады одного мероприятия печатаются одним блоком «Мероприятие (дата)» + нумерованный список докладчиков.
- Публикация считается один раз — у главного автора.
- **Год**: запись относится к году, если её период (дата начала — дата окончания; для стипендии — учебный год) пересекается с этим годом. Стипендия 2025–2026 учебного года попадёт и в отчёт 2025, и в отчёт 2026.

## Каталог показателей (админ, «Настройки»)

Внизу вкладки **«Настройки»** — редактор каталога: формулировки 18 показателей и их подпунктов (изменить, добавить, удалить, переместить), названия видов достижений и их скрытие. Удалить показатель/подпункт, в котором уже есть записи, нельзя. Каталог создаётся при первом запуске (по коду, повторно не перезаписывается).

## Настройки отчёта (админ)

Вкладка **«Настройки»**: название СНО (то, что в кавычках, например `Сельское хозяйство`), надпись над заголовком (по умолчанию «Приложение Е») и таблица подписантов «Должность / ФИО кратко» (строки можно добавлять и удалять). Хранится в таблице `settings`.

## Статистика (админ)

Период (год или «За всё время»), показатели по достижениям и мероприятиям, заседания, график «Достижения по месяцам» (по дате начала), «Топ-5 активных» и подробные таблицы — на данных «Мои достижения».

## Дедупликация мероприятий

Идентичность события: нормализованное название (trim + lower + сжатие пробелов) + тип + дата.

Если такое мероприятие уже есть, новое участие привязывается к нему; иначе создаётся новое. Один человек не может дважды записаться на одно и то же мероприятие. При удалении участника удаляются и его участия.

Мероприятие без участников удаляется автоматически: когда удалено последнее участие (членом совета или админом) или удалён последний участник. Запись в журнале «Заседания и мероприятия», связанная с таким мероприятием, остаётся (связь просто обнуляется). Статистика на всякий случай учитывает только мероприятия с участниками.

## Обновление существующей базы

При запуске приложение само обновляет схему (и SQLite, и Postgres/Neon), не трогая данные:

- создаёт новые таблицы `meetings` и `settings` (`CREATE TABLE IF NOT EXISTS`);
- добавляет недостающие колонки (`events.article_topic`, `events.indexing`, `participations.achievement_number`, `meetings.kind`, `meetings.event_id`) через `ALTER TABLE … ADD COLUMN` (проверка через SQLAlchemy inspector, повторный запуск ничего не меняет);
- один раз удаляет мероприятия без участников, оставшиеся от прошлых версий (повторный запуск ничего не меняет, записи журнала заседаний сохраняются);
- создаёт таблицы годового отчёта `indicators`, `indicator_rows`, `kinds`, `kind_subpoints`, `achievements`, `achievement_people` и заполняет каталог 18 показателей;
- **один раз переносит старые участия в достижения** (повторный запуск ничего не дублирует, старые таблицы `events`/`participations` не меняются): конференция → Доклад (уровень не указан, очно); статья → Публикация (ВАК / РИНЦ / Белый список → соответствующий подпункт, «Без индексации» → публикация без индексации (в отчёт не входит, без предупреждения); главный автор — первый добавивший, остальные — соавторы без долей → «заполните долю», не блокирует); конкурс → п. 3 без уровня; стипендия → п. 8 «иные» (нужно указать учебный год); грант → «Грант» без подпункта. Номер достижения переносится. Записи без уровня/подпункта видны в предупреждениях, пока их не дополнят;
- снимает старое ограничение `CHECK(type IN (...))` у `events.type`, чтобы можно было добавлять стипендии и статьи (Postgres — `DROP CONSTRAINT`, SQLite — пересборка таблицы с сохранением id). Тип теперь проверяется в коде.

Подключение к Postgres использует `pool_pre_ping` и `pool_recycle=300`, а инициализация схемы повторяется до 3 раз с паузой (2 с, 4 с) — на случай, когда бесплатный Neon «просыпается».

## Фирменный стиль

Оформление в стиле сообщества ВК [СНО «Сельское хозяйство»](https://vk.ru/agriculture_dstu): тёмно-зелёный из логотипа и золото с обложки.

- `.streamlit/config.toml` — тема: цвета (`primaryColor = #1B5E34`, фон белый, виджеты `#F4F1E6`, текст `#1C2B21`), шрифты Montserrat (текст) и Unbounded (заголовки) из Google Fonts, скругления, палитра графиков.
- `brand.py` — шапка с логотипом на странице входа и компактная шапка внутри приложения, логотип в боковой панели (`st.logo`), немного CSS (карточки, показатели).
- `assets/` — `logo.png`, `logo_white.png`, `icon.png` (значок вкладки), `wordmark.png` (надпись «СНО — Сельское хозяйство» с обложки ВК).

Название в шапке берётся из «Настройки отчёта» (если задано), иначе — «Сельское хозяйство».

## Smoke-тест (без UI)

```bash
python smoke_test.py
```

Проверяет логику на временной SQLite-базе (рабочая `data/sno.db` не трогается): пользователи и участия, новые типы и статьи, номера достижений, заседания/мероприятия и их связь с мероприятиями участников, настройки, генерация отчёта .docx/.xlsx, статистика по годам, обновление базы старой версии; годовой отчёт: каталог, номера и доли, подсчёт и строки отчёта на данных образца, .docx/.xlsx, отчёт о заседаниях по-прежнему формируется, перенос старых участий (идемпотентно, старые таблицы не меняются). Ожидаемый вывод: `OK`.

Проверка на Postgres — **только на отдельной тестовой базе**, таблицы в ней будут удалены:

```bash
SMOKE_DATABASE_URL="postgresql://user:pass@localhost/sno_test" python smoke_test.py
```
